## Source and interface map
- `MemoryAgent.memorize` calls decorate/decision generation, mutates the memory store, then persists a source page. Fact UUIDs already exist; source-page identity is separately derived from page count. New durable ingest must explicitly unify these records, not merely assign another fact UUID.
- `AdvancedMemoryStore` combines a per-instance RLock with file persistence. The reviewed cleanup boundary, swallowed write errors and age-only file lock remain present at this baseline; the repair PR owns real-class regression evidence.
- `ResearchAgent` accepts retrievers, builds them against its page store and composes search, fusion, integration and reflection. A hosted scope claim requires input/store/index isolation, not only filtering final answers.
- `CheckpointManager` stores arbitrary state via the atomic helper and file lock. It is not an event-range completeness validator.
- `baseline-callers-20260928.txt` records direct lock/cleanup/checkpoint/agent/store references; dynamic/custom stores still need explicit capability checks.

## Runtime decision
The application-linked SQLite engine is **3.51.2**. Its concurrent WAL mode is affected by the upstream [WAL-reset advisory](https://www.sqlite.org/wal.html#walreset). New transactional storage must not silently enable that mode. A documented rollback-journal `DELETE` + `synchronous=FULL` mode is a conservative local default; optional WAL requires an explicitly qualified patched engine. Record actual connection pragmas/source ID when accepting the backend. No global Python/SQLite upgrade is performed by this work package.
